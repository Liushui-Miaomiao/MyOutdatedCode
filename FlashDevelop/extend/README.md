# extend

这项目是当年私下逆向 BVN 3.6 的时候，发现一切关于解密的核心逻辑都是位于主程序的 extend.swf 这个文件，当时其实有直接在 extend.swf 上通过直接编辑 AS 代码来直接返回传入的 SWF 字节流（原始逻辑是将加密的 SWF 字节流通过 extend.swf 里的解密方法解密后返回，破解要做的是跳过解密，直接返回，当然前提是事先拥有了已经解密的 SWF 文件），但我一是觉得直接编辑 AS 代码可能会导致编译的字节码出错，二是觉得不优雅，看了看解密器逻辑其实也相当简单，干脆直接复刻了一个简易的空白解密器，完全没有任何用处，唯一用处就是占住 extend.swf 文件位置直接返回 SWF 字节流实现 “破解”。当然这需要配合其他手段获取已经解密的原始 SWF 文件，这是后话了。
